MTRX3760 Project 1 - ROS controller

This directory contains the wall-following code, ROS build files, startup
files, and controller settings. Bring up the robot or lab simulation
separately before starting the controller. Only one controller should
publish to cmd_vel at a time.

ROS 2
-----
Copy the contents of A2 ROS into ~/turtlebot3_ws/src/mtrx3760_project1.
Use a workspace/package path without spaces. For Humble:
  source /opt/ros/humble/setup.bash
  cd ~/turtlebot3_ws
  rosdep install --from-paths src --ignore-src -r -y
  colcon build --symlink-install --packages-select mtrx3760_project1
  source install/setup.bash
  ros2 launch mtrx3760_project1 wall_follower.launch.py

For Jazzy, source /opt/ros/jazzy/setup.bash before building. Match the
stamped_cmd_vel launch argument to the robot's actual cmd_vel message type:
  ros2 topic type /cmd_vel
Use stamped_cmd_vel:=true for geometry_msgs/msg/TwistStamped; the default
false uses geometry_msgs/msg/Twist. For a simulation, add use_sim_time:=true.
Topics can be changed with scan_topic:=..., cmd_vel_topic:=..., odom_topic:=...

ROS 1 Noetic
------------
Copy the contents of A2 ROS into ~/catkin_ws/src/mtrx3760_project1:
  source /opt/ros/noetic/setup.bash
  cd ~/catkin_ws
  rosdep install --from-paths src --ignore-src -r -y
  catkin_make
  source devel/setup.bash
  roslaunch mtrx3760_project1 wall_follower.launch

Settings and operation
----------------------
Edit config/wall_follower_ros1.yaml or config/wall_follower_ros2.yaml and
restart the controller. Start beside a wall on the robot's right. Distances
are in metres from the laser origin; default speed is 0.10 m/s and target
wall distance is 0.30 m. laser_yaw is the fixed laser-to-robot rotation in
radians; the controller assumes a horizontal laser and does not transform
scans using TF. Validate settings against the physical robot in the lab.
The controller stops on invalid or stale laser data. Ctrl-C publishes zero
velocity before shutdown. A crash or network failure relies on the robot
base's own command timeout.

The node subscribes to scan and odom and publishes cmd_vel and trajectory.
trajectory is an odometry-based nav_msgs/Path for viewing in the lab's RViz
setup (fixed frame: odom). On ROS 2, use Reliable / Transient Local for Path
and Best Effort for LaserScan. Bring up LiDAR and camera through the lab's
robot or simulation setup; this package does not launch them.

Build the controller library locally without ROS, from this directory:
  cmake -S . -B build -DPROJECT1_ROS_VERSION=
  cmake --build build -j4
This only checks the standalone C++ library. The ROS adapters and physical
robot still require building and validation in the lab environment.
Replace the placeholder maintainer email in package.xml before submission.
